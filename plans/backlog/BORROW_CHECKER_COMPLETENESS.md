# The borrow checker's completeness: one enforcement point, five gates, Rust parity

**Status: ACTIVE, O-1 and O-2 landed (2026-11-07; VERDICTS-30, VERDICTS-31; §11).** The design of references and origins is
`plans/backlog/REFERENCES_AND_ORIGINS.md` (O1–O10). This file states how the compiler enforces it in ONE place, what
"complete, without holes" means, the gates that prove it, and the items that bring origins to Rust's expressiveness.
Nothing here changes what the design accepts; it changes where the compiler decides.

Maintainer goals (2026-11-07): "I want Yo's origin model to have the same expressiveness as Rust and I want Yo's
borrow checker to be 'complete' without holes."

**Approved 2026-11-07 by the maintainer** ("for design questions let's do what Fable recommends"): P3's
"no deref coercion" and P6, scoped threads (§7), with the rest. Every item below is binding.

## 1. Why

The advisor's audit (VERDICTS-30, 2026-11-06) found no unsound program the DESIGN accepts, and eight S1 holes in the
BUILT checker on develop: safe programs that `yo check` accepts and that are heap-use-after-free under ASan (seven
confirmed; six also accepted by the v0.2.75 seed, one newly reachable through N1e-2b's read rule). Every one is a
value whose origin set the checker never computed, a lend whose unification it never applied, or a liveness it never
extended. The compiler attaches origins to BINDINGS by syntactic case (a lend, a constructor of lends, a holder copy,
`r := call()`); the design puts them on TYPES. `REFERENCES_AND_ORIGINS.md` §4 ("every lowering is an escape route")
predicted the class. The issues are filed under `issues/2026-11-07-*` (§10).

## 2. The invariants

- A **place** is a path: a local, a parameter, a module-level binding, or one of those followed by field steps, a `.*` through a reference or `Box`, an `Rc`/`Arc` deref, or an index/range projection. Two places overlap iff one is a prefix of the other (decision 18, 28); below an `Rc`/`Arc` deref the cell is the unit; index places on one root overlap conservatively.
- An **origin** is a set of entries `(place, mode)`, mode ∈ {`&`, `&mut`} (VERDICTS-18 §B: the mode comes from the reference that put the place in). An abstract origin parameter `p` is an opaque entry substituted at application (O3 step 1). The empty origin ∅ (`static`) is the set with no entries. The representation on develop (`OriginSet(places : SharedList(String))`) gains the mode per entry and ground place PATHS (today's `LocalBorrowPlace` text) beside parameter names.
- A **loan** is `(holder, origin, live range)`: a binding or a hidden statement temporary holds an origin for a live range (decision 18's last-use range, extended to the scope-end drop when the holder's type reaches a user `Drop`, O3; a loop keeps it live for the whole loop).
- **I0 (well-formedness).** No binding's origin contains its own place; no type names its own fields (O1).
- **I1 (validity).** At every program point, for every live loan and every entry `(q, m)` in its origin, the owner of `q` is alive, `q` has not been moved, and `q` has not been written or dropped since the loan began unless through a `&mut` reference whose origin contains `q`.
- **I2 (exclusivity).** For every live loan with an entry `(q, &mut)`, no other live loan has an entry overlapping `q`, and every access to a place overlapping `q` during the live range goes through a reference whose origin derives from that loan (a reborrow). For `(q, &)`: no live `&mut` entry overlaps `q`, and no write, move or drop of a place overlapping `q` occurs.
- "**`&` means unchanged**" (`plans/VALUES_BY_DEFAULT.md` §3.10) is the corollary of I2 for `&` entries, and is what the verifier's alias reasoning consumes.

## 3. The architecture: one origin per expression, five functions

**The record.** `ExprInfo.origin : Option(TypeValue)` — an `OriginSet` with `(place, mode)` entries — is filled for every expression whose type carries an origin (`type_carries_origin`), by the evaluator, bottom-up, at the one place each node is typed. `.None` on such an expression is a compiler error (E13xx "origin not computed"), never a silent empty set: that is the totality check of §6 G-E.

**The computation `origin_of(e)`** (the design's rules restated per node; every rule is already in O1–O10, decisions 18/24/25/26/28/35/37/38):

| Rule | Node | `origin_of` |
| --- | --- | --- |
| R-LEND | `&place`, `&mut place` | `{(place, mode)}`; a temporary operand is a hidden statement local (R-TEMP) |
| R-READ | a reference binding read as a reference value (R1's positions) | the binding's slot origin (its elided origin is the binding's own place for a lend `r := &x`: `{(x, &)}` — VERDICTS-23's `reference_binding_read_type`) |
| R-DEREF | `r.*` as a place | the place `r.*`; `&r.*` is a reborrow: `origin_of(r)` ∪ `{(r, &)}` when `r` is reached through a `&` path and holds `&mut` (O3 reborrow), else `origin_of(r)` |
| R-FIELD | `e.f` where `f`'s type carries an origin | the composite's entries restricted to the field's origin parameters, substituted (N1e-2a) |
| R-COMP | a constructor, tuple, array, enum payload, record literal | the union of the components' origins |
| R-ARM | `match`, `cond`, a block tail, `return(e)` targets of one function | the union over the arms (decision 38 A "borrow sets join"); the arm bindings of a borrowed scrutinee carry the scrutinee's origin (decision 26) |
| R-CALL | a call `f(args)` or method call | the callee's declared result origin (spelled, or O2's elided union of the reference-holding parameters) with each parameter name substituted by `origin_of(arg)` — O3 step 1. A projection is this rule with the result origin naming the lent parameter |
| R-CLOSURE-LIT | a closure literal | the union of its captures' origins (a `&`/`&mut` capture is R-LEND of the captured place; a by-value capture of an origin-carrying value is its origin) |
| R-CLOSURE-CALL | `c(args)` | R-CALL over the closure's signature: `Fn` lends `c` `&`, `FnMut` lends `c` `&mut`, `FnOnce` moves `c`; the result origin's elided default is the union of `c`'s own entry and the parameters' per-call origins — so a `&mut` capture returned is `&mut(T, c)` and two live results of one `FnMut` are the ordinary E0911 on `c` (decision 37) |
| R-ASYNC | an `io.async` literal | the union of its captures' origins (N3-1's stamp); `io.await(f)` is a consuming call of `f` |
| R-CTL | a `ctl` operation call | R-CALL over the operation's signature; a handler's `return(e)` is checked as the operation's result (O7); a handler body names no runtime local of the installer (`REFERENCES_AND_ORIGINS.md` O7) |
| R-GLOBAL | a lend of an unmarked module-level binding | ∅ (decision 47; `static`); of a `mut(G)` binding: `{(G, mode)}` with decision 18 rule 3 at the access |
| R-COPY | a `Copy` read or a move of an origin-carrying value | the same origin (route 3) |
| R-NONE | an expression whose type carries no origin | no set (not `.None` — the type says so) |

**The five functions** (the only entry points; everything else in `local_borrow_*` becomes an implementation detail of these or is deleted):

1. `origin_of(e)` above.
2. `bind(holder, origin, range)` — registers one loan per entry. Called at `:=`, at `=` (the holder's set becomes the join over reaching definitions, including the loop back edge), at a destructuring, at a `match`/`for` arm binding, at a parameter binding of a closure/async body (rigid entries), at a hidden statement temporary (R-TEMP).
3. `access(place, kind)` — `kind` ∈ {read, write, move, drop, lend-`&`, lend-`&mut`}; checks every live loan's entries against `place` by overlap and mode, E0911 (by a binding) or E0910 (by a call's argument set, decision 28). Called from every place read, write, move, drop, lend, receiver and argument evaluation — one call site per node kind, listed in §5.
4. `lend_through(param_slot, arg)` — at a call: substitutes the callee's origin parameters from the arguments; an origin reached through a `&mut` pointee, a `RefCell` payload or a `&mut` capture unifies EXACTLY (O3-3); a flow-inferred set on the caller's side is an inference variable solved by the unification and written back to the holder after the call (§7 "flow inference at a `&mut` lend"); a spelled set that fails the subset check is E0923 at the argument. This is the one place O3 steps 1 and 3 are applied; it covers free functions, methods, closure calls, `Dyn` dispatch, `ctl` operations and `io.async` captures alike because they all go through R-CALL.
5. `return_check(origin)` — at `return(e)` and the body tail: every entry names an origin parameter or a reference-typed parameter's place (O3 return rule; E0912 for a local, E0923 for a parameter the spelled result does not name); inside a closure/async literal the parameters' per-call origins and the body's locals are rejected, the captures' origins are accepted (they outlive the value).

**Liveness** is decision 18's, computed once per holder from `bind`'s range; a holder whose type reaches a user `Drop` (transitively through fields, payloads, elements and cells — `REFERENCES_AND_ORIGINS.md` O3, "Drops that use no root") is live to its scope-end drop.

**What this deletes:** `origin_carrying_value_roots` and the T9 lend records (`calls/helper.yo:994–1085`, `utils.yo:8468–8694`), `local_borrow_may_bind_projection_stmt`'s look-ahead, the closure half of `g_capture_borrows` and `type_carries_origin`'s registry walk, `note_second_class_binding`/`reject_second_class_return`/`second_class_slot` (the second-class caste becomes `return_check` + `Escapable`), the three binding flags (`is_ref`, `is_imm_borrow`, `is_borrow_match_binding` — the slot type says it), `g_reference_reads` (the read rule's verdict is the ExprInfo type), `g_local_borrow_step_pins` (decision 25's pins become entries with an `Rc`-deref flag). `src/types/flowability.yo` (1,476 lines, the pre-origin `_reject_if_container_reachable` machinery) is reduced to the `Rc`-path marks of decision 28.

## 4. The soundness argument over the architecture

By induction over program points, assuming I0–I2 hold before each node:

By induction over program points, assuming I0–I2 hold before each node:

- **Creation (R-LEND, R-GLOBAL):** a new loan's entries name a place that exists at the lend and is checked by `access(place, lend-mode)` against every live loan — I2 holds for the new loan at creation; I1 holds because the place is alive now and every later write/move/drop/`&mut`-lend of it calls `access`, which sees this loan while it is live.
- **Propagation (R-COMP, R-ARM, R-FIELD, R-COPY, R-DEREF):** an origin is never smaller than its sources' union, so a value's loans cover every loan of every value it was built from; a reborrow through a `&` path adds the path's holder (the holder stays frozen). Over-approximation preserves I1/I2 (an extra entry only rejects more).
- **Calls (R-CALL, `lend_through`):** the callee's body was checked once per type instantiation with its origin parameters rigid (O1), so its result's entries are a subset of what its signature names; substitution maps those to the caller's argument origins, which are live loans by the argument `access` checks (decision 28's call-scoped lends). Exact unification through a `&mut` pointee means a callee cannot store a wider origin than the caller's holder declares (O3-3; this is H1/H4's rule); a flow-inferred holder's set is widened to the solved value, so a later access to the widened places is checked (§7's rule).
- **Binding (`bind`):** a holder's loans are the join over reaching definitions (loops to a fixpoint); its live range ends at the last use, or at the drop for a `Drop`-reaching type — so a root's scope-end drop before that drop is an `access(root, drop)` conflict (H6's rule).
- **Return (`return_check`):** a result names only places the caller owns (parameters' lent places, origin parameters), so the caller's loans, created by R-CALL, name places alive in the caller's frame (route 1).
- **Closures/async/handlers:** a literal's parameters are rigid per-call origins and its captures are loans held by the closure value (R-CLOSURE-LIT); a store from a parameter into a capture or another parameter fails `lend_through`'s exact unification (H2's rule); a call of the value is a method call with the receiver lent in the trait's mode (decision 37), so results that derive from `&mut` captures carry the receiver's entry (I2 by the ordinary E0911 on the closure binding).
- **Cells and sharing (O9):** an entry through an `Rc` deref names the handle's place; the handle is frozen, so the count never reaches zero while the loan lives; `RefCell` payload borrows go through guards whose place is the entry. **No-origin positions (O4/O10):** `Escapable` is structural; a value with entries never crosses them.
- **Completeness** (the new claim): because every node of an origin-carrying type has a set (G-E), every loan is in the table (`bind` is the only registrar), and every access of the kinds in I1/I2 calls `access` (§5's table is the exhaustive list, enforced by G-E's grep gate), there is no program point where a loan exists that the checker does not know, or an access the checker does not see. The eight holes of VERDICTS-30 were each a value whose set was not computed (H3, H5, H7, H8, L1), a lend whose unification was not applied (H1, H4, H2), or a liveness not extended (H6): each is a missing call to one of the five functions, which is what the totality audit catches.

## 6. "Done": the five gates

Adopt all five. "Done" for a release means G-A, G-B and G-E green on the tip, G-C with an empty unexplained-divergence list, and G-D having run at least one nightly without a new counterexample.

- **G-A — the corpus `target` set as a Tier-1 gate.** `PHASES="N1 N2 N3" YO=<tree binary> bash scripts/origins-corpus.sh target` (about 5 min, one core) is Tier 1 for any PR touching `src/evaluator/utils.yo`, `calls/function.yo`, `calls/helper.yo`, `memory_safety.yo`, `exprs/match.yo`, `exprs/begin.yo`, `values/anonymous_function.yo`, `codegen/exprs/async.yo` or `expr.yo`'s desugars. In CI it is a job `origins-corpus` in `test.yml` (one runner, the tree binary from the build job), in `merge-gate`'s `needs:`. The manifest gains the ~14 new rows of §7 and §10 and the `today` column is re-recorded once (VERDICTS-30 §2.2 item 8).
- **G-B — `tests/origins/unsound/`, the ASan must-reject directory.** Every S1 hole's program (the `h*` and `p59`/`p60` probes with heap payloads) lives there with a header `// expect: E09xx`. The runner (`scripts/origins-unsound.sh`): `yo check` must FAIL with the expected code; if it passes, the program is compiled with `--sanitize address --allocator system` and run — a UAF/ICE is reported beside the missing rejection, so a regression is never silent. Positive controls (the same shapes with the write after the last use) are compiled and run under ASan too. CI: inside the `origins-corpus` job (about 3 min more). Tier 1 for the same files as G-A.
- **G-C — the rustc differential corpus.** Each corpus row gains a `.rs` twin in `tests/origins/rust/` where the models coincide (holders, lends, calls, arms, closures, drops; NOT `Rc` handle origins, effects, async, `mut(G)` lends, `.*`-only reads). `scripts/origins-diff-rustc.sh` runs `rustc --edition 2021 --emit=metadata` on each twin and compares accept/reject with the Yo verdict; `tests/origins/rust/DIVERGENCES.tsv` lists every row where the verdicts differ with its reason (an over-freeze Yo accepts as a design position, a shape Yo rejects pending a parity item, Polonius cases Rust rejects). An unexplained divergence fails the job. Rust is the oracle only where the design says the models coincide — the file states that. CI: a job `origins-rustc-diff` on the Linux runner with rustc pinned (the version in `rust-toolchain`-style pin, `1.97`), weekly on `develop` plus on any PR that edits `tests/origins/`. Not Tier 1.
- **G-D — a generator of borrow programs.** An enumerative generator (`scripts/origins-gen.py`, Python, ~400 lines) over a grammar of: 2–3 roots (`i32`, `String`, `Rc(X)`), holders (`Option(&T)`, a 1-field `H(p)`, a 2-field `S(p)`, `Box`), creation sites (lend, constructor, arm, call result, closure call, `for` element, projection), sinks (`:=`, `=`, place write, `&mut`-lend to a `store`/`put`, capture store), an invalidating event (write, reassign, drop, scope end, growth, `Rc` reassign), and a read-after. It emits the Yo program AND its rustc twin from one template; for each: Yo's verdict, rustc's verdict, and when Yo accepts, an ASan run. A disagreement or a UAF is minimized by dropping template dimensions and written to `tests/origins/gen-findings/` as a candidate corpus row. Budget: 10 minutes nightly (a few hundred programs), `YO_GEN_SEED` for reproduction. CI: a scheduled workflow `origins-generator.yml` on `develop`, nightly, with the findings directory as an artifact and an issue opened by the workflow on a new finding. Not Tier 1; the finding becomes a corpus row (G-A/G-B) by a PR.
- **G-E — the totality and sink audit.** Two mechanical checks, both Tier 1 for the files of G-A and both in the `origins-corpus` job: (1) `YO_AUDIT_ORIGIN_TOTALITY=1 yo check` over `./src`, `./std`, `tests/origins/corpus` and the language tests that name a reference (the `ref_*`, `local_borrows`, `impl_ref`, `origin_*`, `for_macro_borrow*`, `async_await` files): the evaluator aborts on any node whose type carries an origin and whose `ExprInfo.origin` is `.None`, and on any `bind`/`access` reached with a `.None` set; the count must be 0. (2) `scripts/check-origin-sinks.sh`: a grep gate that the only callers of `local_borrow_register` are `bind`, the only callers of the conflict check are `access`, and that every node-kind file in §5's table calls `access`/`bind`/`lend_through` at least once (a table in the script, one line per lowering). Adding a lowering means adding its line.

How a hole found later is handled: it is a G-B program first (failing), then a corpus row, then the fix; never a fix without the row. This is the "corpus before rules" discipline of N0 applied to every bug.
