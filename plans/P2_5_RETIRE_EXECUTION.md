# P2.5 — retiring `src/`: the measured execution plan

**Working doc for item 2.5 of [`P2_RETIRE_SRC.md`](P2_RETIRE_SRC.md).** Same
contract as its parent and as [`P1_CLI_PARITY.md`](P1_CLI_PARITY.md): every
number is measured, the doc records what is done and what is in flight, and
traps go in as they are found. Written 2026-08-11.

Provenance: a six-dimension read-only audit of the whole repo — CI workflows,
root toolchain + `scripts/`, docs/instructions/skills, CLI surface parity
(`src/yo-cli.ts` vs `yo-self/main.yo`), sub-CLI logic parity, and the TS test
corpus — with every dimension adversarially re-verified by a second pass. 226
raw findings, 67 corrections to those findings, 47 items the first pass missed.

**The headline: 2.5 is not a deletion, it is nine prerequisites and a
deletion.** The umbrella doc's inventory was optimistic in three places that
would each have caused SILENT damage — the two wasm legs, the TSan leg, and the
VS Code extension's language server all depend on `src/` with no self-hosted
replacement, and all three fail without a red signal (green CI, a shipped
extension with no server, unsanitized test runs). Spot-verified 2026-08-11:
`src/codegen/async/runtime-io-wasm.ts` is 832 lines with no
`yo-self/codegen/async/runtime_io_wasm.yo` at all (the dispatcher
`__yo_panic`s: "WASM async I/O runtime is a Phase-5 follow-up"); the TSan leg's
entire mechanism is `YO_TEST_SANITIZE`, read only by `src/test-runner.ts:558`
(zero hits in `yo-self/`); and `yo test` consumes-and-discards
`--cc`/`--c-compiler`/`--target`/`--test-batch-size` (`yo-self/main.yo:1233`).

Those corrections are applied in the parent doc; the table below records what
they replaced, because "we believed the wasm legs would just work" is the kind
of thing a future session needs to be able to see.

### Risks and traps

- **A stage-2-only bug is invisible to every CI arm that tests a TS-built stage-1.** This is not hypothetical: the fixpoint divergence traced to the C `i64.MIN` literal was invisible to all stage-1 arms, and the v0.2.0 seed's mis-compile of current `yo-self` (`issues/fixed/seed-built-stage1-miscompiles-current-source.md`) is the same shape. After 2.5 every arm is stage-2-class, which _exposes_ that bug class — and simultaneously makes a bad seed able to poison everything. **Recovery:** the `src-attic-final` tag, and bootstrapping from an older release tag; keep `fixpoint_only.sh` + `hollow_sweep69.sh` as the ratchets they are.
- **A red seed leg blocks the release.** #98 promotes macos-x64 and windows-x64 to `experimental: false` (`origin/p2/ci-migration:.github/workflows/release.yml:246-258`), and after step 24 those legs are also _seed-built_. A single unbuildable target then stops the release, and the seed chain has no fallback unless the trust-chain policy names one (previous-release-builds-next, with "bootstrap from an older tag" as the escape).
- **`SEED_VERSION` drift is enforced by nothing but memory.** Add a check (e.g. a job asserting the pin is the latest published release, or a release-workflow step that bumps it).
- **`install-seed` treats a 404 as a warning.** Combined with an unread `installed` output, a retired leg degrades to a bare `yo` — either "command not found" or an unrelated `yo` on PATH. Fix before converting a non-Linux leg (B4).
- **Goldens must be recorded before the attic tag**, from the SELF arm (`cli-diff-test.sh:231` injects `YO_STD` on that side only). Recording them after `src/` is gone is impossible; recording them from the TS arm bakes in an env asymmetry.
- **Silent hollowness is the dominant failure mode of this phase.** Four conversions report green while testing nothing: `yo test --target`/`--c-compiler` (consumed and dropped, `main.yo:1233`), TSan without `YO_TEST_SANITIZE`, the language suite without ASan, and a batch `__yo_user_main` that is a "Failed to transpile" comment (the reason `hollow_sweep69.sh` exists). **Every converted leg needs a positive assertion that the intended flag reached clang**, not just rc=0.
- **Branch-protection required checks are named by job name** and are not visible from the filesystem. Deleting the 4-shard job or renaming steps can leave PRs blocked on checks that never run.
- **`bun test` goes red before `src/` is deleted** (B8) — the meta-tests assert the workflow text being changed.
- **`yo.lock` churns on the next `yo fetch`.** TS writes `name = "…"`; yo-self column-pads (`yo-self/lock_file.yo:163-167`). Both parsers tolerate either, but deleting `src/` picks yo-self's format silently and rewrites every committed lock file. Pick one writer format first.
- **The `yo-self/` → `src/` rename decision must precede the docs sweep** (step 29) or ~90 live-doc paths plus the whole `plans/`+`issues/` corpus gain a second translation.
- **Windows native probe SEGVs (rc=139) on the child-compile-failure error path** — only reachable when a compile fails; tracked in `issues/fixed/windows-native-selfhosted-build-fails.md` (iteration-3 note). Converting the Windows leg's probe to the seed makes that path reachable in CI.
- **Do not run two `yo test` invocations concurrently** during local verification: `macro_expansion` alone needs 6.52 GB, two children on 16 GB swap, and the swapping trips the runner's own 600 s deadline — manufacturing failures that do not reproduce in isolation.

## Notes on individual steps, from scoping (2026-08-11)

**Steps 4 and 6 are ONE refactor, not two.** The runner spawns each test with
`tcmd.status(io)` (`yo-self/main.yo:1408`), which returns only an exit status.

the ASan `detect_leaks is not supported` retry (TS reads the combined output and
re-runs with `detect_leaks=0`, `src/test-runner.ts:806-820`), `-v/--verbose`
failure output (TS prints the captured output on failure — which is why a bare
`✗ <name>` is all yo-self can show), and TS's capture-then-print display
generally. `Command.output(io)` already exists in std and is used elsewhere in
yo-self (`build_runner.yo:109`, `doc_command.yo:84`), so **no std change is
needed** — but the switch turns streaming into buffering for every self-hosted
test run, a visible change to three jobs' CI logs. Do it as one PR.

Two further facts for that PR:

- `std/process/command.yo` has **no per-command environment.** The runner already
  works around this by mutating the PARENT env before spawning

  portable wrapper, not libc `setenv`, which Windows lacks).
  `ASAN_OPTIONS`/`LSAN_OPTIONS` must take the same route.

  `leak:libdyld`, `leak:libxpc`, `leak:libsystem_malloc`, `leak:dyld` —

## Release-process traps found while cutting v0.2.2 (2026-08-11)

Both cost a CI cycle and neither is discoverable from the code:

- **`SEED_VERSION` can only name a PUBLISHED release.** Releases are created as
  drafts and flipped public by `publish-release` only after every required
  bundle leg uploads (the atomicity that keeps `latest` from pointing at a
  bundle-less release) — and **a draft release's assets 404 on the public
  download URL.** Pinning the seed to a still-draft v0.2.2 failed all four
  seed-driven jobs at the download. Measured: v0.2.2's asset URL returned 404
  while draft and 200 once published; v0.2.1's returned 200 throughout. The pin
  and `install-seed`'s error message now both say so.
- **A seed-built stage-1 inherits the PREVIOUS RELEASE's `std`** unless the build
  passes `--std-path`. The seed self-locates the `std/` bundled beside its own
  `bin/`, so `yo compile yo-self/main.yo` under a seed on PATH produces "current
  `yo-self/` sources + the previous release's std" — a hybrid that never ships,
  which hides std regressions from every seed-driven job and can manufacture
  failures. Measured at the binary level 2026-08-11, using the already-fixed
  cross-allocator free as a tracer (it prints two `mi_free: invalid pointer`
  lines per compile):

  | binary                                            | invalid frees | std it embeds  |
  | ------------------------------------------------- | ------------- | -------------- |
  | stage-1 built by the v0.2.2 seed, no `--std-path` | 2             | the seed's     |
  | stage-1 built by TS from the fixed tree           | 0             | the checkout's |
  | the v0.2.2 release binary itself                  | 2             | as shipped     |

  All four stage-1 builds in test.yml now pass `--std-path ./std`. Note the flag
  also short-circuits resolution BEFORE `current_exe()` is called, so a probe
  that passes `--std-path` cannot observe this — the first attempt at the
  measurement was vacuous for exactly that reason.

- **A native self-build needs swap on a 16 GB runner.** Converting stage-1 from
  TS to the seed raised peak memory from `node --max-old-space-size=4096`'s cap
  to a native self-emit's ~9-11.5 GB. The tier-1 gates job died with "The hosted
  runner lost communication with the server" (GitHub stored **no log at all**
  for it, and its step still read `in_progress` — that combination IS the
  starvation signature, not a gate failure), while the other two converted jobs
  survived the same profile by luck. Every job that builds a stage-1 natively
  needs the 32 GB `/mnt` swap step the fixpoint job already had.
- **A codegen fix takes TWO GENERATIONS to reach a seed-built binary.** Measured
  2026-08-12 with the awaited-RC-result dup fix
  (`issues/fixed/self-built-compiler-uaf-in-report-and-build-paths.md`). A stage-1
  built by the OLD seed from FIXED sources is a hybrid: what it **emits** is
  correct (0 shallow-copy warnings in its output, because its codegen logic comes
  from the fixed sources), but what it **is** still carries the defect (it still
  corrupted the free list), because the old seed compiled it. So:

  | binary                                           | emits correctly? | is correct?                                                                                           |
  | ------------------------------------------------ | ---------------- | ----------------------------------------------------------------------------------------------------- |
  | old seed                                         | no               | yes (it was TS-built)                                                                                 |
  | stage-1 built BY the old seed from fixed sources | **yes**          | **no** — the 27-case corpus scores PASS 15 / DIFF 3 / SELF-FAIL 5 / BOTH-FAIL 4, IDENTICAL to pre-fix |
  | stage-1 built by TS from fixed sources           | yes              | yes                                                                                                   |
  | stage-1 built by a seed cut AFTER the fix        | yes              | yes                                                                                                   |

  Consequence for every codegen fix from here on: **land the fix, cut a release,
  THEN bump `SEED_VERSION`** — a seed-driven CI arm cannot go green on the fix
  until the seed itself was built from the fixed compiler. This is exactly why
  #100's fix needed v0.2.2 before 2.3 could be attempted, and it will be the
  standing cost of every codegen fix once `src/` is gone and the chain has no TS
  shortcut. Budget one release per codegen fix that affects the compiler's own
  compilation.

- **A conflicted PR gets NO `pull_request` run, silently.** When a PR's merge
  commit cannot be computed, GitHub creates no run at all: no annotation, no
  failed check, nothing in `gh run list`, `total_count: 0` for the head SHA. Two
  pushes vanished this way before `gh pr view --json mergeable` showed
  `CONFLICTING`. And after resolving it, one MORE push was needed — the
  synchronize event fired while the stale conflicted merge ref was still cached.
  When a push produces no run, check mergeability first.

## Prep slice landed 2026-08-11 (branch `p2/retire-prep`)

Four items from Group B, plus the bug the probing surfaced. Everything here is
measured; where a verification is partial that is stated as such.

- **A shipped allocator bug, found by looking at the test runner's stderr.**
  `current_exe()` took its canonical path from `realpath(pbuf, .None)` — a
  buffer from libc's malloc — and released it through `GlobalAllocator`, which
  is `mi_free` under `--allocator mimalloc`. Every v0.2.0/v0.2.1 bundle printed
  two `mi_free: invalid pointer` lines and leaked two `PATH_MAX` blocks per
  compile (two because the std-path walk-up calls `current_exe()` twice).
  Fixed by passing our own buffer; verified 3 invalid frees → 0 with a
  three-call probe, and 2 → 0 for the compiler itself.
  `issues/fixed/current-exe-realpath-cross-allocator-free.md`.
  **Both smokes now capture the compiler's stderr and fail on
  `mimalloc: error`** (test.yml's per-leg native probe, release.yml's bundle
  smoke) — the class had no detector before, which is why it shipped twice.
- **Test names carried their quotes.** The runner read the name from the raw
  StringLit token (`"name"`), so it printed `✓ "name"` where TS prints `✓ name`
  (TS reads the EVALUATED comptime string, `src/test-runner.ts:316`) and
  `--test-name-pattern` matched against the quote characters. The file already
  had a correct `extract_test_name` that strips them — dead code, never called.

  both compilers select the same single test for an exact-name pattern and
  print the same name. **Residual (step 6):** yo-self still does not print
