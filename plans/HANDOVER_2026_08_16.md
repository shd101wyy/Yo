4. **`platform`/`arch`/`pointer_size_bits` folded from the HOST, not the target**
   — the known `issues/yo-self-cross-emit-host-constants.md`, reached from a
   second direction. Fixed by porting TS's `currentTarget`

   `yo-self/target.yo`), published by `run_compile` BEFORE evaluation.
   **Also fixed a latent 2× error**: `__yo_pointer_size_bits` returned the host's
   64 for wasm32 targets.
5. **`-sEXIT_RUNTIME=1` with `-sSTANDALONE_WASM`**, which emcc rejects outright.

## 4. THE BLOCKING BUG — full investigation state

`issues/yo-self-unsubstituted-type-param-emits-duplicate-struct.md` has the
canonical writeup. This section is the working summary.

### 4.1 Symptom

yo-self emits TWO C structs for `Box` where TS emits one:

| C struct  | Yo type                   | correct?                   |
| --------- | ------------------------- | -------------------------- |
| `__yo_t1` | `Box(<enum:enum_decl_…>)` | yes                        |
| `__yo_t2` | **`Box(V)`**              | **no — `V` unsubstituted** |

Bodies are byte-identical, so C mixes `__yo_t1*` and `__yo_t2*` →
`incompatible pointer types`. **Warning** on clang 21 (local), **error** on
emcc 6.0.6 (CI) and on clang 16+/GCC 14+ generally.

### 4.2 Blast radius — verified, not assumed

- **v0.2.7 is NOT affected.** Every shipped artifact is TS-emitted
  (`release.yml:342` seed, `:408` portable arms, `:482` musl); TS emits zero of
  these diagnostics.
- **The deadline is Group E.** Deleting `src/` makes yo-self the release
  emitter, at which point this ships. It gates `src/` deletion.
- **yo-self already emits type-incorrect C on NATIVE builds today** — hidden
  only by clang's leniency. Currently-green jobs will start failing as CI images
  modernise.

### 4.3 Reproducer — 16 lines, seconds to run

`issues/repros/unsubstituted-box-typaram.yo`:

```rust
TreeNode :: enum(
  Leaf(value : i32),
  Branch(left : Box(Self), right : Box(Self))
);
derive(TreeNode, Clone);
```

```bash
<stage1> compile issues/repros/unsubstituted-box-typaram.yo \
  --release --emit-c --skip-c-compiler -o /tmp/r
grep -cE '^struct __yo_t[0-9]+_struct \{ // Box\(V\)' /tmp/r.c   # 1 now, want 0
```

TS on the same file emits `1` Box struct and `0` `Box(V)`.

### 4.4 Trigger matrix (7 variants, zero rebuilds)

| #   | shape                                              | leak  |
| --- | -------------------------------------------------- | ----- |
| A   | enum + `Box(Self)` + `derive(Clone)`, via `box()`  | **1** |
| B   | enum + `Box(Self)` + `derive(Clone)`, direct ctor  | **1** |
| C   | enum + `Box(Self)`, no `Clone` impl                | 0     |
| D   | struct + `Box(i32)` + derive                       | 0     |
| E   | struct + `Box(Self)` + derive                      | 0 ⚠  |
| F   | enum + `Box(i32)` non-recursive + derive           | 0     |
| H   | enum + `Box(Self)` + **hand-written** `Clone` impl | **1** |

**Required: ENUM + recursive `Wrapper(Self)` + a `Clone` impl that clones the
wrapped payload.**

- **B kills the `box()`-inference theory** — leaks with no `box()` call at all.
- **H kills the derive theory** — leaks with no `derive` at all. `__derive_clone`
  is innocent.
- **E vs A/H is the sharpest signal**: same shape as a struct is CLEAN. The
  divergence is in the ENUM path.
- ⚠ **E IS UNFINISHED AND MAY BE A FALSE NEGATIVE.** Its `main` never calls
  `.clone()`, so the impl may never have specialized. **Redo E with a real
  `.clone()` call before trusting the struct/enum split.** This is the first
  thing to do.

Structural difference that likely matters: the struct derive emits
`self.field.clone()` (field access on a concrete instance), while the enum arm
emits a **match binding** `__v_<name>.clone()` whose type comes from the variant
declaration (`std/prelude.yo:6711-6806`, `__derive_clone`).

### 4.5 Eliminated by measurement — do NOT re-derive

| hypothesis                                      | verdict                                            |
| ----------------------------------------------- | -------------------------------------------------- |
| The re-eval machinery never runs                | ❌ `_resolve_type_arg_somes` runs 1683×            |
| Its collector doesn't see `Box(V)`              | ❌ collects it 13×                                 |
| Type-arg `V` ≠ field `V` (stale copy)           | ❌ **same SomeT id, 1138**                         |
| Forall-name mismatch                            | ❌ both literally `V` (`prelude.yo:7382`, `:7390`) |
| The occurrence-substitution fallback never runs | ❌ it runs                                         |
| Its gate conditions aren't met                  | ❌ `nsomes=1 nforall=1 nargs=1`                    |

The machinery for this exact bug ALREADY EXISTS and is wired
(`yo-self/evaluator/types/function.yo:4772-4790` documents the symptom verbatim:
_"a raw SomeT in an argument slot emits a SECOND C struct with the same
layout"_). It runs, sees `Box(V)`, and binds nothing (`bound_any=NO`, 13/13).

**Localized to the substitution loop at `yo-self/evaluator/calls/helper.yo:2328-2371`**
(occurrence substitution, comment names `List(U)`). Measured directly:

```
pre  ret=Box(V)  nsomes=1  nforall=1  nargs=1
post ret=Box(V)                                  ← unchanged, twice
```

It has one SomeT, one forall named `V`, one inferred arg — and substitutes
nothing.

### 4.6 Next probe (unfinished)

Three candidates remain inside that loop. Distinguish by printing what the
inferred forall arg holds:

1. `arg_values.forall_args[0].value` is `.None` (V not yet inferred here);
2. it holds a `TypeVal` that is itself a SomeT (the `!is_some_type` guard rejects it);
3. `zs_any` is set but `substitute()` doesn't rewrite → fault is in **level**
   matching, not the map. Note `yo-self/types/substitution.yo:85,102` key on
   `(name, level)` with exact `usize` equality, where TS
   (`src/evaluator/values/impl.ts:2203`) keys by **name alone**. This is a real
   ported-in divergence and a strong candidate.

A parallel investigation (workflow) produced four more candidate cause-sites
worth reading before you code: `yo-self/evaluator/calls/function.yo:1876/1895`
(the `rte` want/accept gates), `helper.yo:2481/2517` (same, at the mint),
`helper.yo:2221-2302` (the "declared-param bridge", whose comment names `box`),
and `function.yo:2270-2311` (adopted-then-overwritten). It also found TS's actual
mechanism: TS **re-evaluates the return-type EXPRESSION** by name in the callee
env (`src/evaluator/types/function.ts:2836-2844`) rather than resolving a
TypeValue — because `Box` is a comptime _function_, re-evaluation genuinely
invokes `Box(TreeNode)` and hits the specialization cache, guaranteeing one
struct. yo-self ported that as a **gated fallback**, not TS's unconditional
mechanism.

### 4.7 Two fixes RULED OUT — with the failure each causes

1. **Filtering `Box(V)` at the emission site** (deep `type_contains_some_type`):
   that `Box(V)` is the declared C return type of a REAL emitted function
   (`repro_self.c:414`), so filtering makes `get_type_string` miss and
   `_lookup_named_c_type` **PANIC** (`yo-self/codegen/utils/index.yo:810-816`).
   Five clang warnings become a compiler abort.
2. **Unifying the two types' identity** so they collapse to one C struct (this
   was a workflow's recommendation): hides the symptom and leaves a function
   whose declared return type is a type parameter.

**If deferral is chosen anyway**, the only acceptable shape is a per-file
`pragma(Pragma.SkipWasm32Wasi)` + `SkipWasm32Emscripten` on
`tests/derive_clone_complex.test.yo` **with a comment stating the test is fine
and the compiler is broken**, plus the issue link. 55 test files already use that
mechanism. Do **not** suppress `-Wincompatible-pointer-types` on the emcc line —
that hides the whole class across all 188 files and all future code.

### Instrumentation gotcha that cost THREE build cycles

`eprintln` inside a `match` arm whose sibling is a bare `()` fails the whole
build with:

```
Error: Frame level N has different number of values for different cases.
```

The error names a frame LEVEL, not a file or line, so it points nowhere near the
edit. **Put probes at function-body statement level**, or use file-level helper
functions whose bodies are SINGLE balanced expressions. Recorded (as a measured
lead, not a verified rule) in `.github/instructions/yo-syntax.instructions.md`.
