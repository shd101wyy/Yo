# 可流动性（Flowability）—— 默认安全的引用

Yo 在编译期保证：安全代码无法构造出悬垂引用。这一设计是**构造即正确**
（sound by construction）：安全语言中根本没有任何方式能形成指向可重分配
存储的指针，因此经典的失效陷阱（增长列表导致借用悬垂）不是被某种聪明的
分析"拒绝"的 —— 它们*无法表达*。

## `inout` 能出现在哪里

`inout` 是 Yo 的二等引用，它只存在于**两个**位置：**参数位置**和
**局部绑定位置**。`inout(name) : T` 接收调用者的左值（可写回，大结构体
免拷贝）；接收 inout 的回调参数（`body : Impl(Fn(inout(v) : T) -> R)`，如
`Mutex.with_lock`）是同一机制向下传递一层。`inout(name) := place;` 则在
所在块的余下部分里，把 `name` 绑定到 `place` 所指的存储：

```rust
x := i32(1);
inout(y) := x;        // y 命名 x 的槽位
y = i32(2);           // 写入 x
x = i32(5);           // y 读到 5：绑定命名的是槽位，不是某个值
inout(n) := h.n;      // RC 对象的字段：h 指向的对象在此作用域内被钉住
inout(px) := p.x;     // 值结构体的字段
copy := y;            // 拷贝被指向的值 —— 不存在可存储的"inout 类型"
```

局部绑定接受与实参相同的**位置（place）**（见下），并多出一种：经过 RC
对象到达的字段（`h.n`、`a.b.n`）是允许的，并会**钉住**最内层的对象 ——
一个隐藏的持有局部让它一直存活到绑定的作用域结束，`break`、`return`
与效应 `unwind` 一视同仁 —— 因此重新赋值或丢弃可见句柄都不可能释放绑定
所命名的存储。绑定禁止两件事：**在绑定存活期间移动它的根**（作用域内有
`inout(y) := x` 时 `sink(own(x))` 是编译错误 —— 先把值拷出来，或先结束
绑定的作用域），以及**元素位置**（`xs(i)`、`p.*`）：指向集合存储内部的
指针没有绑定可以钉住的所有者。绑定只能是局部的（不能在模块级）、暂不能
出现在 `io.async` 体内、且只能用 `:=`。

**函数不能返回 `inout`**；inout 也不能存入字段、被闭包捕获、或出现在泛型
类型内。inout 在调用边界或绑定处出生、随所在作用域消亡 —— 它永远不可能
比它指向的存储活得更久。

传给 `inout` 参数的实参是一个简单的左值**位置（place）**：

- 完整变量（任何作用域 —— 变量槽位是稳定存储）；
- 以**局部变量或参数**为根的 `var.field`（或 struct 字段路径）——
  该位置位于根对象的分配内部，调用者的句柄会让它在整个调用期间存活；
- 经过中间 **object**（如 `a.b.s` 中 `b` 是 object 字段）的链，以及
  以**模块级**变量为根的字段链都会被拒绝 —— 被调用者可能替换该句柄的
  槽位并释放被借用的存储。修复只需一行：先把对象绑定到局部
  （`b := a.b`）—— 局部句柄会自然地钉住它；
- **索引元素**（`xs(i)`）或经过**中间 object** 的链（包括 `Box` 解引用
  `b.*` —— `Box` 是普通 object，`*` 只是字段名）是指向堆对象存储内部的
  指针；只有当被调用者无法接触到该对象时才能作为 inout 实参 —— 同一次
  调用中传入该容器/box（或别名）、索引模块级容器，或传入**任何其他
  object/闭包实参**（可能持有它的句柄），都会被拒绝（增长或重新赋值会
  在引用之下释放存储）。仅元素的用法（`to_string(xs(i))`、`${xs(i)}`、
  `bump(xs(i))`、`owner_box.*.id.clone()`）安全且合法；要在一次调用中
  同时使用元素和容器，先用 `.get(i)` 把元素拷出来。

> **运行时后挡。** 有一种形态可以绕过静态实参可达性检查：容器先逃逸进
> **全局**堆结构（`g.push(xs); bump(xs(i))`，其中 `bump` 通过全局增长
> `xs`）。静态封闭它需要全程序逃逸分析。一个轻量级的运行时借用标志
> （RC 头部的 `borrow_count`，利用现有填充字节，零额外内存）封闭了该残留：
> 被调用者触发确定性 panic（`"container operation while an interior reference
borrows from it"`）而非内存破坏。同缓存行加载 + 预测分支 —— 实测约
> ~0% 开销。

## 元素访问：句柄与拷贝，而非内部指针

容器只交出**值**，从不交出指向其缓冲区内部的指针：

```rust
e := xs.get(i);          // object 元素：指向元素对象的句柄
e.push_str("!");         //   就地变异元素；句柄在 xs.push / realloc 之后
                         //   依然有效 —— 它指向 String 对象本身，
                         //   而不是 xs 的缓冲区内部
xs(i) = v;               // 索引写：就地替换元素
t := xs.get(i).unwrap(); // struct 元素：拷出 ……
xs(i) = t2;              //   …… 再写回
for(xs, (x) => { ... }); // 迭代是值形式（into_iter）
```

元素也可以被**借用**，但只在一个地方：借用形式的 `for`。

```rust
for(enemies, inout(e) => { e.hp = (e.hp - i32(1)); });   // struct 元素就地修改
for(names, inout(s) => { s.push_str("!"); });            // RC 元素：每个元素不再 dup
for(counts, inout(c) => { bump(c); });                   // 把元素交给 inout 参数
for(scores, (k, inout(v)) => { v = (v + i32(10)); });    // map：键按值、值被借用
```

宏会把集合绑定到一个隐藏局部变量（循环期间它不可能被释放），在整个循环
期间持有该集合的**运行时借用标志**，并通过指针迭代器 `iter()` 把每个元素
绑定为指向集合自身存储的 `inout` 局部 —— 这也是 `iter()` 存在并交出 `*(T)`
的原因：它是 `for` 消费的协议，而不是给用户代码用的 API。`break`、
`continue`、`return` 与效应 `unwind` 都会释放该标志。标志被持有期间，任何
可能使元素失效的操作 —— 增长、收缩、删除，无论作用在集合自身还是经由任何
别名 —— 都会**确定性地 panic**（`container operation while an interior
reference … borrows from it`），而不是让元素引用悬垂。这是 Yo 的安全保证中
唯一以运行时检查而非编译期拒绝实现的地方（Swift 对共享存储的模型）：编译器
会在每个可能修改对象的 RC 对象方法入口自动插入该断言（由方法体判定 ——
Yo 没有 `mut`），因此任何集合 —— 无论 std 还是第三方 —— 都无需标注即可
获得保护。该判定按参数逐个进行，并追踪每个被修改值的存储位于何处：只修改
自己分配的存储的方法（`clone` 向其结果 push、`collect`），或用 `for` 遍历集合
的方法，不带断言；把新建存储存入 `self` 之后再修改它的方法则带断言。只读方法
（`len`、`get`、`contains`、`index_of`、`==`、`clone`、迭代）零开销；修改方法在
入口付出一次加载比较（在纳秒级的 `push`/`pop` 微基准上约 7–9 %，其他场景不可
测量）。对 map
使用普通的 `inout(e)` 会交出整个条目；请优先使用 `(k, inout(v))`，它保持键
不可变。`Array(T, N)` 没有 `iter()`，请使用值形式或索引循环。在会挂起的
`io.async` 体内（真正的状态机），`inout` 绑定与借用形式的 `for` 暂不可用，
请在那里使用值形式。

两项可选的收紧把剩余的运行时情形提前到编译期。`pragma(Pragma.StrictBorrow);`
让该文件中借用循环体内的每个调用都必须被编译器证明不会使元素失效，否则报编译
错误：对被借用集合（或其同帧别名）的修改方法会被拒绝；效果未知的被调用者
—— 闭包或 `dyn` 调用、函数指针、效应处理器、带回调的 extern、经由全局变量或
原始指针触及存储的函数体 —— 同样被拒绝。只读方法、`clone`、`collect`、经由
`x` 的元素写入以及对其他集合的调用都被接受；出路是把调用移出循环，或先复制
集合。与该 pragma 无关的另一项：安全代码不再能*持有*原始指针值 —— 指针迭代器
的 `it.next()` 交出 `Option(*(T))`，在没有 `pragma(Pragma.AllowUnsafe)` 的文件
中是错误（标准库作为经审计的可信基础除外），因此借用形式的 `for` 是安全代码借用元素的唯一途径（`count`、`map`
等不暴露指针的迭代器组合子仍然可用）。

`project` 与 `Indexable` 已不存在。`str` 仍然是永生的静态字节视图（自由
复制、无约束），区间索引**拷贝**（`arr(a..b)` 返回新 `ArrayList`），所以
修改源永远不会影响结果。

## 一条调用点规则

**同一次调用不得把同一个对象同时作为 inout 扎根的实参和 `own` 实参传入**
（`use_and_sink(h.s, h)` 配 `own(victim)` 会被拒绝）—— `own` 把调用者
的引用计数移交给被调用者，而后者可能在借用仍被使用时释放它。不同对象
没有问题；按值重叠也没有问题：借用的句柄永远无法释放调用者的计数
（把它转交给 `own` 位置会先 dup）。

没有了局部绑定，就没有任何东西可"失效"：旧的借用失效门已随绑定形式
一并删除。`get` 返回的元素句柄在任何容器操作之后都有效 —— 即使容器被
重新赋值 —— 因为句柄对元素对象持有 +1。

## 逃逸通道

`pragma(Pragma.AllowUnsafe);` 豁免整个文件（标准库经过审计的内部实现使
用它）；`unsafe(expr)` 标记单个表达式。裸指针 `Index` 实现
（`index : … -> *(T)`）是热循环确有测量需求时受支持的零拷贝逃逸通道。
参见 [MEMORY_SAFETY.md](./MEMORY_SAFETY.md)。
