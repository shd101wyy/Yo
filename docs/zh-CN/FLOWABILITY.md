# 可流动性（Flowability）—— 默认安全的引用

Yo 在编译期保证：安全代码无法构造出悬垂引用。这一设计是**构造即正确**
（sound by construction）：安全语言中根本没有任何方式能形成指向可重分配
存储的指针，因此经典的失效陷阱（增长列表导致借用悬垂）不是被某种聪明的
分析"拒绝"的 —— 它们*无法表达*。

## `ref` 能出现在哪里

`ref` 是 Yo 的二等引用。它只出现在两个位置：

- **参数位置** —— `ref(name) : T` 接收调用者的左值（可写回，大结构体免
  拷贝）。接收 ref 的回调参数（`body : Impl(Fn(ref(v) : T) -> R)`，如
  `Mutex.with_lock`）是同一机制向下传递一层。
- **局部左值借用** —— `ref(r) := lvalue;` 借用一个局部变量、`ref` 绑定
  参数的字段、或 object 的字段。

**函数不能返回 `ref`。**返回的 ref 将是指向调用者可重分配/可释放存储的
指针；编译器在签名求值时直接拒绝 `-> ref(T)`（及带标签形式）。ref 也
不能存入字段、被闭包捕获、或出现在泛型类型内 —— 它们永远不会比下方的
栈帧活得更久。

因此每个安全的 `ref` 都扎根于**栈帧槽位**（按构造比被调用者长寿）或
**object 字段** —— 而 object 的分配永不移动。对 object 字段借用，编译器
还会**钉住（pin）所有者**：`ref(r) := h.s` 在借用作用域内对 `h` 的对象
持有 +1（每个*绑定*两次引用计数操作，不是每次访问），因此无论何处存在
别名，对象都不可能在借用存活期间被释放。

## 元素访问：句柄与拷贝，而非内部指针

容器只交出**值**，从不交出指向其缓冲区内部的指针：

```rust
e := xs.get(i);          // object 元素：指向元素对象的句柄
e.push_str("!");         //   就地变异元素；句柄在 xs.push / realloc 之后
                         //   依然有效 —— 它指向 String 对象本身，
                         //   而不是 xs 的缓冲区内部
xs(i) = v;               // 索引写：就地替换元素
t := xs.get(i).unwrap(); // struct 元素：拷出 ……
xs(i) = t2;              //   …… 再写回
for(xs, (x) => { ... }); // 迭代是值形式（into_iter）
```

`project`、`Indexable`、以及 `for` 的借用形式都已不存在 ——
`for(coll, ref(x) => …)` 会产生带迁移指引的编译错误。`str` 仍然是永生的
静态字节视图（自由复制、无约束），区间索引**拷贝**（`arr(a..b)` 返回新
`ArrayList`），所以修改源永远不会影响结果。

## 借用失效诊断

当 `ref(r) := …` 绑定存活时，其借用所扎根的变量不得被**重新赋值**、
**移动**、用作**方法接收者**或**调用实参**、或**取别名**（`h2 := h`）——
每一种都是指明借用位置的编译错误。已存在的别名同样受约束（标记作用于
整个别名组），从同一所有者创建另一个借用仍然允许。约束随绑定所在块结束
而解除。这些门是钉住机制之上的*诊断层*：在犯错的那一行抓住错误，而不是
让 pin 默默延长对象生命周期。

一条跨函数规则补全整个故事：**同一次调用不得把同一个对象同时作为
ref 扎根的实参和 `own` 实参传入**（`use_and_sink(h.s, h)` 配
`own(victim)` 会被拒绝）—— `own` 把调用者的引用计数移交给被调用者，而
后者可能在借用仍被使用时释放它。不同对象没有问题；按值重叠也没有问题：
借用的句柄永远无法释放调用者的计数（把它转交给 `own` 位置会先 dup）。

## 逃逸通道

`pragma(Pragma.AllowUnsafe);` 豁免整个文件（标准库经过审计的内部实现使
用它）；`unsafe(expr)` 标记单个表达式。裸指针 `Index` 实现
（`index : … -> *(T)`）是热循环确有测量需求时受支持的零拷贝逃逸通道。
参见 [MEMORY_SAFETY.md](./MEMORY_SAFETY.md)。
