# 可流动性（Flowability）—— 默认安全的切片与引用

Yo 允许安全代码自由使用 `Slice(T)`、`str` 以及 `ref(name) : T` 借用，但**安全代
码无法构造出悬垂的切片或引用**。在编译期提供这一保证的检查称为**可流动性
（flowability）**。

平常你几乎不需要关心它 —— 标准库的写法已经让常见用法自然通过。本文解释当编译器报
出 *"the expression is not flowable"* 时背后的规则，以及给编写"对外暴露借用视图"
的底层代码的人参考。

## 它解决的问题

`Slice(T)` 是一个*胖指针* —— 一对 `(数据指针, 长度)`，指向它并**不拥有**的存储。
`str` 形状相同。`ref(name) : T` 参数是指向调用者变量的二等指针。它们都不会让其背后
的存储保持存活。一旦其中之一逃逸到比该存储更长寿的位置，之后读取它就是一次**释放后
使用（use-after-free）**：

```rust
// 被拒绝 —— 会悬垂。
first :: (fn() -> Slice(i32))({
  local := ArrayList(i32).new();
  local.push(i32(7));
  match(local.as_slice(), .Some(s) => s, .None => panic("empty"))
  // 本帧返回时 `local` 的堆缓冲区被释放；
  // 返回的切片会指向已释放的内存。
});
```

可流动性正是在编译期拒绝这一类逃逸，零运行时开销，也无需任何生命周期标注。

## 模型："值必须流入比它更长寿的存储"

当编译器能够**纯结构化地**证明：被存入的值，其背后存储至少与目标位置一样长寿时，这
个值就对该目标是**可流动的（flowable）**。这里没有生命周期变量；证明沿着表达式的语
法回溯到一个生命周期已知的*根（root）*。

可流动性只约束那些其表示**可传递地携带裸指针**的值 —— `Slice(T)`、`str`、`*(T)`，
以及任何包裹了它们的 `struct` / 元组 / `enum` / `Array`。普通的 `i32`、`bool`、自有
的 `String` / `ArrayList`（它们拥有随值一起转移的引用计数缓冲区）以及其它自包含的值
永远不受约束 —— 它们没有任何可悬垂的东西。

## 在哪些位置强制执行

检查在五个"借用视图可能被存入更长寿存储"的位置运行：

| # | 位置 | 示例 |
|---|------|------|
| 1 | `-> ref(T)` 函数返回 | `fn(ref(b) : Slice) -> ref(i32)` |
| 2 | 携带裸指针的值返回 | `fn(...) -> Slice(i32)` / `-> str` / `-> 含切片的结构体` |
| 3 | `ref(name) := expr` 局部绑定 | `ref(r) := p` |
| 4 | 简单重新赋值 `name = expr` | `cur = other_slice` |
| 5 | 字段 / 下标 / 解构写入 | `holder.s = x`、`arr(0) = x`、`(a, b) = (x, y)` |

## 什么算作可流动的来源

编译器遍历表达式时，会接受下列这些根。不同位置接受的集合略有差异（函数*返回*比局部
*绑定*更严格，因为返回值必须比整个调用更长寿）：

- **`ref` 绑定的名字** —— `ref(name) : T` 参数或 `ref(name) := …` 局部。它指向某个
  仍活跃的调用者帧中的存储，因此比本次调用更长寿。*（所有位置。）*
- **任意参数**（不限于 `ref`）—— 调用者的实参值在整个调用期间存活，因此以它为根的切
  片可以返回给调用者。*（返回 + 绑定/赋值位置。）*
- **`comptime` 值或字符串 / 字符字面量** —— 它存于静态存储，运行时永不悬垂。*（所有
  位置。）*
- **外层作用域的局部** —— 其作用域*包含*（因而比目标更长寿）目标的局部。在绑定
  （`ref(r) := local`）以及重新赋值/字段写入位置接受，但在**函数返回位置不接受**（被
  调用方的局部永不比调用者长寿）。对于 `name = expr` 重新赋值或 `holder.s = expr` 字
  段写入，来源局部所在作用域的深度必须不深于目标容器所在作用域。

## 结构化规则

从表达式向内遍历，满足下列任一即为可流动：

- **R1 —— 名字。** 上面列表中的某个可流动来源。
- **R2 —— 投影 `base.field`。** 当 `base` 可流动时可流动。（从可流动聚合体中投影出
  字段，得到的借用根相同。）
- **R3 —— 返回借用的调用。** 返回槽为 `ref(T)`（或在切片返回位置为携带裸指针的值类
  型）的调用，当每一个可能成为该借用*来源*的实参 —— 其 `ref` 类型参数，以及可能支撑
  结果的切片/object 参数 —— 自身都可流动时，该调用可流动。（因此 `slice.project(i)`
  当 `slice` 可流动时可流动。）
- **R4 —— `cond` / `match`。** 当**每个**分支都可流动时可流动。一个悬垂分支即污染整
  个表达式。
- **构造器** —— `.Variant(args)`、`Struct(field : arg)` 以及元组 `(a, b)`，当每个其
  表示携带裸指针的实参/元素都可流动时可流动。（新构造的聚合体只能通过其参数夹带指
  针。）带标签的实参 `field : value` 是透明的 —— 真正流动的是其*值*。

最终保证：每个可流动表达式的根都是编译器确知比目标更长寿的东西，因此存入的视图永不悬
垂。

## 示例

```rust
// 接受 —— 从 `ref` 参数投影出切片；缓冲区属于调用者，比本次调用更长寿。
window :: (fn(ref(buf) : Slice(i32)) -> Slice(i32))(buf);

// 接受 —— 两个 match 分支都以参数 `seed` 为根。
pick :: (fn(seed : Slice(i32), other : Slice(i32), c : bool) -> Slice(i32))(
  cond(c => seed, true => other)
);

// 拒绝（位置 5，字段写入）—— 把指向内层块局部的切片存入外层结构体字段，会让它比其背
// 后存储更长寿。
SliceBox :: struct(s : Slice(i32));
store :: (fn(seed : Slice(i32)) -> unit)({
  (holder : SliceBox) = SliceBox(s : seed);
  {
    tmp := ArrayList(i32).new();
    tmp.push(i32(1));
    holder.s = match(tmp.as_slice(), .Some(s) => s, .None => seed); // ✗
  };
  ()
});
```

## 逃逸通道

声明了 `pragma(Pragma.AllowUnsafe);` 的文件完全退出流动性闸门（它已被信任可以使用裸
指针）；在任意文件中，`unsafe(expr)` 表达式都被视为可流动 —— 这是有据可查的"我已检
查过"标记。标准库的底层投影（`Slice`、`ArrayList`、`String` 的下标）正是这样做的：用
指针算术计算元素地址，再把结果包进 `unsafe(...)`，从而在经过审计的不安全内核之上向调
用者提供安全 API。参见 [MEMORY_SAFETY.md](./MEMORY_SAFETY.md)。

## 范围与限制

可流动性是一种**结构化的、基于作用域嵌套**的证明，而非完整的借用检查器。它保证被存入
视图的背后*作用域*包含该视图的目标。它有意**不**追踪以下两点：

1. **借用存活期间背后存储被失效** —— 即切片失效（slice-invalidation）问题。可流动
   性证明的是背后存储的*作用域*包含借用；它不追踪该作用域内部替换或移动背后缓冲区的
   事件。共有三种触发方式，目前都会被接受：

   ```rust
   buf := ArrayList(i32).new();
   buf.push(i32(42));
   s := match(buf.as_slice(), .Some(x) => x, .None => panic("e"));

   buf = ArrayList(i32).new();   // (a) 重新赋值 —— 旧缓冲区被释放
   buf.push(i32(1));             // (b) 超出容量的增长 —— realloc 移动缓冲区；
                                 //     `s` 仍指向旧缓冲区
   alias := buf;
   alias.clear();                // (c) 通过 Rc 别名进行的变更 —— 效果相同，
                                 //     任何按变量的分析都无法看到
   ```

   上述任一发生后，读取 `s` 都是未定义行为 —— 通常表现为*悄无声息的脏读*，而非崩
   溃。这是作用域嵌套模型的已知边界。彻底关闭它要么需要别名感知的借用独占性（Rust
   式借用检查器，与 Yo 的共享可变 `object` 模型冲突），要么需要改变 `Slice` 的表示
   （例如共同拥有其缓冲区的快照切片）—— 设计讨论见
   `issues/slice-invalidation-design.md`。

2. **`unsafe` / pragma 代码。** 按设计，闸门不在那里运行。

在这些边界之内 —— 安全代码、背后存储没有在作用域内被移动 —— 悬垂的切片或引用是**无法
构造的**。
